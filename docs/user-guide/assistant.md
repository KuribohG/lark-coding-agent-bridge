# 会话助理

[手册首页](README.md) · [盯盘来源](monitoring.md)

会话助理统一展示待办、分析、草稿和处理状态。当前有两类来源：飞书消息和 GitLab CI。飞书消息采集默认关闭，CI 在自己的配置中独立开启。

## 开启飞书消息来源

1. 在本地控制台创建并启动个人 Claude 或 Codex profile。
2. 打开会话助理的“配置与首次使用检查”，点击“授权飞书消息读取”，在浏览器完成后点击“完成授权”。
3. 应用和用户需具备消息读取能力：`search:message`、`im:chat:read`、`im:message.p2p_msg:get_as_user`、`im:message.group_msg:get_as_user`。租户需要审批时先完成审批。
4. 将机器人加入专用的结果话题群，在目标话题中 @机器人发送 `/inbox setup`。回控制台点击“重新读取设置”，填入本人和结果位置。
5. 在“模型 API 服务”中添加筛选服务，再在助理中选择；深入分析模型可留空，跟随执行 profile。
6. 填写“本人职责与关注范围”，选择接收范围，执行“检查配置”，确认后开启并保存。

检查配置不发送模型请求。第一次实际运行后，仍需查看筛选和分析是否成功。

职责可以写成“我维护项目 A 的发布流水线；同事明确交办给我的失败排查需要跟进；其他团队的通用网络告警通常不归我处理”。具体职责和待采取动作比关键词列表更有用。

| 接收范围 | 内容 |
| --- | --- |
| 私聊 | 当前授权用户可读取的私聊 |
| 私聊和 @我 | 私聊，加直接 @本人的群消息及相关回复 |
| 全部 | 当前授权用户可读取的私聊和群消息，仍要经过关注筛选 |

开启或扩大范围从新消息开始，不批量补入历史会话。需要分析已有会话时，用工作台“主动选择会话分析”。

## 飞书消息如何成为待办

```text
采集消息 → 合并相关内容 → 判断是否需要本人处理 → 排队深入分析 → 草稿与证据 → 本人核对处理
```

筛选可能补查相关飞书资料，结果分为需要处理、无需动作、待核对和暂未完成。新的“需要处理”事项自动进入分析队列；查询失败会重试，不直接猜成需要处理。群成员身份、领域词汇或告警严重等级本身不会证明你负责。

开始分析前会在配置的结果位置建立或确认话题。完成后，结果和草稿发到该话题；工作台也能查看。消息不会由助理自动发给原会话中的对方，草稿由你核对、复制并发送。

Agent 允许调查分析及可回滚的本地准备，任务要求把发信、push、合并、部署等外部操作留给用户确认。每项飞书待办分析默认最长 30 分钟，执行器需保持在线。支持超时配置的版本可在“会话助理 → 配置与首次使用检查 → 高级设置”修改“深入分析超时（分钟）”，范围为 1–1440，包含重试等待。新值用于后续启动的分析，当前任务保留原时限。

## 在工作台处理事项

用 `run-lark-cc ui` 打开本地控制台，进入会话助理：

- **全部来源 / 飞书会话 / GitLab CI**：筛选任务来源。
- **待处理**：需要本人关注、正在分析或已有草稿但尚未处理的事项。
- **筛选与待核对**：尚在判断、等待查询重试等事项。
- **历史**：已处理、忽略或无需动作的记录。

点开事项查看来源链接、分析证据、缺失信息和草稿。CI 事项还显示本机证据目录。

| 操作 | 结果 |
| --- | --- |
| 保存草稿 | 保存你的修改；旧页面不能覆盖新版本 |
| 复制草稿 | 复制到剪贴板，由你核对后发送 |
| 分析 / 重试 | 显式提交新分析，要求相应来源已开启 |
| 已处理 | 表示你已完成跟进；停止该事项的在途工作 |
| 忽略 | 排除该事项并停止处理，保留历史 |
| 恢复待办 | 重新开放事项；盯盘事项需再点“分析 / 重试”才运行 |

生成草稿不等于“你已处理”。人工修改或忽略后，旧任务晚到的结果不能覆盖你的决定。批量操作要选择同一来源；跨来源选择会整体拒绝，提示分开操作。

当前没有独立的“只停止这一次分析且保留开放状态”按钮。需要终止事项处理可以标记已处理或忽略；需要暂停整个来源见下一节。

## 暂停和恢复

“暂停接收”控制飞书消息来源，会取消其正在筛选、排队和分析的任务。历史和草稿仍可查看编辑，相关执行 profile 需在线。**独立开启的 CI 来源继续运行。** 停止 CI 要在 CI 配置中关闭，停止全部后台工作则关闭整个 Bridge。

不同来源使用同一分析队列，在同一 Bridge 进程内一次执行一项深入分析。飞书轻量筛选可以继续并行；GitLab 轮询也可以继续发现问题。重启中断的分析保留为失败，需手动重试；已经完成的结果不会因为投递重试而重新分析。

## 避免回收自己的输出

助理会排除自身机器人消息及已配置的结果群。CI 结果可发到同一个结果群，但 CI 待办是直接提交到任务入口的，不靠重新读取机器人消息生成。

本地消息事项保存在配置目录下 `inbox/state.sqlite`；盯盘事项按来源及账号分区保存在 `inbox/sources/` 下各自的 `state.sqlite`。旧版 `state.json` 会在首次升级时导入并归档。已处理事项有清理策略，工作台不是永久档案库，重要结果应另行保存。

可选远程工作台同步同一所属用户、同一执行 profile 的来源事项；跨 profile 汇总和来源筛选以本地工作台为准。远程页面能否展示新的来源字段取决于其前端版本。原有飞书简版卡片 / H5 入口仍以会话来源为主。

更多筛选、重试和权限细节见[会话助理机制参考](../inbox-assistant.md)。
