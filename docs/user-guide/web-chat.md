# Web 聊天：启动、使用与排错

[手册首页](README.md) · [配置教程](configuration.md) · [Windows](windows.md)

这篇只讲 **Bridge Chat 独立聊天页**。它不需要飞书，不包含机器人管理、会话助理或模型服务编辑表单。`lark-channel-bridge ui` 打开的是另一套[飞书管理控制台](getting-started.md)。

## 第一次启动

先按[快速开始](quick-start.md#2-安装一次)完成安装，并确认本机 Agent 能直接对话。以下命令在仓库根目录执行：

```sh
node bin/lark-channel-bridge.mjs web --agent codex --workspace . --state-dir .web-local/chat --port 8787
```

把工作目录改成实际项目。例如 Windows：

```powershell
node bin/lark-channel-bridge.mjs web --agent codex --workspace "C:\projects\my-app" --state-dir .web-local/chat --port 8787
```

macOS / Linux 使用相应绝对路径；其余参数相同。Codex / Claude 默认使用 workspace 权限，Pi 不支持 workspace 沙箱，独立 Pi Web 的默认权限为 full。不要在不了解权限范围时切换引擎。

### 打开哪个地址

终端输出形如：

```text
Bridge Chat: http://127.0.0.1:8787/#token=<本次启动生成的令牌> (engine: codex)
```

打开**你自己的实际完整链接**；上面的占位符不能直接使用。第一次加载后，页面把令牌保存到当前浏览器会话，并清除地址栏里的 `#token`，这是正常现象。

- 每次重启服务都会换令牌，旧链接会失效。
- 新浏览器、无痕窗口或新的浏览器会话需要重新打开完整链接。
- 在已有标签页只替换 `#token` 不一定重新加载脚本；粘贴新链接后再刷新。
- `127.0.0.1` 指打开浏览器的那台机器；手机上的这个地址不是你的电脑。
- 不要把带令牌的地址公开。它是操作本机 Agent 的凭据。

## 页面怎么用

页面分三块：左边是对话列表，中间是当前对话，右边是按需打开的工作流面板。

| 控件 / 动作 | 行为 |
| --- | --- |
| 消息框 | Enter 发送，Shift+Enter 换行；可在设置里改成 Ctrl/⌘+Enter 发送。没发出去的草稿按对话保留，刷新页面不丢，关掉标签页才清除 |
| 运行中发送补充 | 支持的引擎会接收追加文字；“已接收”不代表已完成，送达未知时不要盲目重发 |
| 停止 | 取消当前运行，不撤销已写文件或已完成操作 |
| 新对话 | 创建新的对话上下文；不是清空项目目录。快捷键 Ctrl/⌘+Shift+O |
| 对话列表 | 按最近活动排序，可搜索、重命名、置顶、删除；正在运行的对话有标记。运行中的对话要先停止才能删除 |
| 引擎选择 | 在消息框下方，仅在空闲时切换；目标 Agent 必须已安装，并满足当前权限要求 |
| `/` 命令 | 在消息框输入 `/` 会列出可用命令：`/help`、`/new`、`/status`、`/stop`、`/model`，以及 `/workflow …` |
| `/workflow …` | 例如 `/workflow start <任务>`、`/workflow status`、`/workflow cancel`；运行中也可以发。工作流的计划、通知和主会话被唤醒后的回合都会显示在对话里 |
| 工作流面板 | 标题栏的“工作流”按钮打开；列出这个对话的工作流，点进去是只读的概览、成员、任务队列和留言，随进度刷新 |
| 工具进度 | 每次工具调用一行，点开看输入和输出；可在设置里改成默认展开，或由 `channels.web.show_tools` 整体隐藏 |
| 提问卡片 | Agent 需要你做选择时出现在对话里，选完提交即可；阻塞式提问会让运行等你回答 |
| 命令面板 | Ctrl/⌘+K：搜索并跳到某个对话，新建对话，显示或收起侧栏和工作流面板，切换主题，打开设置 |
| 设置 | 浅色 / 深色 / 跟随系统，发送键，工具默认展开。只保存在当前浏览器 |

Ctrl/⌘+B 收起或展开对话列表。窄屏（手机宽度）下对话列表变成抽屉。

建议第一条消息是：“只说明你能看到的项目，不修改文件。”确认模型回复后，再给出真正任务。

**飞书的 `/cd`、`/config` 等管理命令在 Web 里不可用。** 输入 `/` 时列出的就是全部可用命令；项目、模型和权限在启动参数或配置中设置。

## 工作目录、模型和配置

| 参数 | 用途 |
| --- | --- |
| `--workspace <路径>` | 必填；已有目录，固定为此服务的项目 |
| `--agent codex\|claude\|pi` | 初始引擎；无配置、无参数时默认 Claude |
| `--binary <路径>` | 初始引擎的可执行文件；程序不在 PATH 时使用 |
| `--model <id>` | 初始引擎本次服务的新任务模型覆盖 |
| `--config <文件>` | 显式读取 Bridge TOML；不自动读取管理控制台的配置 |
| `--profile <名称>` | 需要 `--config`；选择其中的 profile，而非默认 active profile |
| `--state-dir <目录>` | 会话状态存储；不传时为 `~/.lark-channel/web/default` |
| `--port <端口>` | 默认 8787；传 0 时自动分配空闲端口，以输出地址为准 |
| `--state-file <文件>` | 把本次启动的地址、令牌和进程号写进这个文件（仅本人可读，退出时删除），给本机的代理或启动器用 |

`LARK_CHANNEL_HOME` 不会替代独立 `web` 的 `--state-dir`。希望状态落在固定目录时显式传入它。

不用 Bridge 配置也能沿用 Agent 已有账号和模型。要配置模型服务、展示或执行默认值，参见[配置教程](configuration.md)。独立 Web 不监听配置文件变化，保存后需重启。

### Windows 后台与独立 Codex home

已有自定义 Responses provider 时，可以改用：

```powershell
.\bin\windows\start-web.ps1 -Workspace "C:\projects\my-app" -OpenBrowser
.\bin\windows\stop-web.ps1
```

该脚本读取原生 Codex 配置里的 `model_provider`、对应的 Responses 服务和默认模型，在 `<StateDir>/codex-home` 建立独立状态。密钥只注入子进程环境，不复制登录文件、桌面插件或通知命令。仅 OAuth 登录、不支持的鉴权或缺少凭据时会明确拒绝，**不会自动借用其他账号**。

脚本接受 `-Workspace`、`-StateDir`、`-Port`、`-OpenBrowser`，不接受 Bridge `--config`。需要 Bridge TOML 时使用上面的标准 CLI。详细数据位置和停止方式见 [Windows 指南](windows.md)。

## 停止、重启和续接

1. 先让任务结束，或点击“停止”。
2. 前台模式按 Ctrl+C；脚本模式执行对应的 `stop-web.ps1`。`lark-channel-bridge ui --stop` 不会停止独立聊天页。
3. 使用相同项目、状态目录和端口重新启动。
4. 打开新的完整 token URL，刷新页面后继续提问。

任务在服务端运行，不依赖页面连接：运行中关闭或刷新页面不会取消任务，重新打开后会接着显示进度、结果和尚未回答的提问；要取消请点“停止”。服务重启会结束运行中的任务。

对话记录保存在服务端的 `<state-dir>/web-chat`：`index.json` 是对话列表，每个对话一个只追加的 JSONL 文件。因此换浏览器、清理站点数据、重启服务之后，用同一个状态目录启动就能看到同样的对话列表和历史；浏览器本地只保存界面设置和当前标签页里没发出去的草稿。备份或迁移时连同整个状态目录一起处理。

几点边界：

- 记录里的工具输入、输出过长时会截断显示；Agent 自己的会话不受影响。
- 服务重启时还在运行的任务会在记录里标为“已中断”，没回答的提问不再等待。
- 记录是给人看的历史。Agent 是否还记得上文取决于原生 session：`/new`、改变工作目录或权限后，历史还在，但 Agent 从头开始。
- 删除对话会同时清掉它的记录和 Agent 会话，不能撤销。

Windows 脚本强停后，状态锁最多约 30 秒过期，重启脚本会等待，不应手动删除状态目录或锁。

## 在远程服务器运行

服务仍只监听服务器的回环地址。在你的电脑建立 SSH 转发：

```sh
ssh -N -L 8787:127.0.0.1:8787 user@your-server
```

然后使用 `http://127.0.0.1:8787/#token=<服务器打印的令牌>`。换了本地转发端口，对话历史照旧（在服务端），只有界面设置和草稿要重新来。不要为省去转发而直接向公网开放此服务。

## 放在已有登录的代理后面

浏览器只能访问某个已有登录的服务（例如 JupyterHub、内部门户）时，可以让它把一个路径转发到聊天页，不用 SSH 转发：

- 页面的所有请求都相对自己的地址，挂在任意路径前缀下都能用，例如 `https://host/user/me/chat/`（末尾要有 `/`）。
- 用 `--state-file` 启动，代理从这个文件读地址和令牌，转发时加上 `x-ui-token` 请求头。浏览器拿不到令牌，打开代理地址即可，不需要带 `#token` 的链接。
- 代理向服务发请求时不要带浏览器的 `Origin`，`Host` 用服务自己的地址：服务只接受发给 `127.0.0.1` 的请求。
- `api/stream` 是一条长连接，代理要边收边发、不能缓冲，也不能设短超时；服务每 20 秒发一行心跳。
- 谁能用这个页面，由代理的登录决定。能打开它就能在这台机器上以启动者的身份运行 Agent，转发前必须确认登录，并防住跨站请求。

代理完全走不了 HTTP 时，承载页面的文档可以在页面脚本运行前定义 `window.__bridgeChatFetch`，约定与 `fetch` 相同（包括流式响应体），页面的全部请求改走它。

## 故障排查

| 错误 / 现象 | 处理顺序 |
| --- | --- |
| `unauthorized` / 提示从启动链接打开 | 获取最近一次启动的完整链接；已有标签页重新加载 |
| 连接被拒绝 | 检查进程还在、端口正确、浏览器与服务是否同机；先看启动终端 |
| `EADDRINUSE` | 端口被占用；确认是不是已有实例，不要盲目终止别的进程；换端口或停止自己的实例 |
| 状态目录已被使用 | 同一个 `--state-dir` 只运行一个实例；停止旧实例后等待锁过期 |
| 找不到 Agent | 同一用户下执行 `codex --version` 等检查；必要时显式传 `--binary` |
| `CODEX_HOME ... does not exist` | 检查显式 home 路径；不要随意设置 `inheritCodexHome = false`，隔离 home 必须自行初始化 |
| `already has an active writer` | 原生 Codex home 可能被其他应用使用；自定义 Responses 场景可使用隔离启动器 |
| 模型 401 / 403 / 额度错误 | 直接检查 Agent/provider；Web token 与模型 API key 是两种不同凭据 |
| 模型服务配置没生效 | 标准 CLI 有没有传正确 `--config`、是否重启；后台隔离脚本使用的是原生 provider 配置 |
| 模型已答复，但日志有 `post-done-exit-timeout` | CLI 未在退出宽限期内结束，Bridge 会尝试清理；核对结果和子进程，不要扩大权限来消除日志 |

启动错误看终端；`--state-dir` 下的 `logs` 保存运行日志。Windows 脚本另有 `web.stdout.log`、`web.stderr.log`；只提供必要的脱敏错误，不公开 token、密钥和完整个人配置。
